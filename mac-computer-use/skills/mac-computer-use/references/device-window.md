# Simulator device window

`simulator {"action":"window","device":"<UDID>"}` opens the actual simulator framebuffer in a native AppKit window. The LCD and thin device body are opaque. Only the area outside the device and controls is transparent; preview opacity affects previews alone. There is no standard title bar or traffic-light buttons.

- **Move:** drag **⠿ 이동** or the device name/status in the capsule above the device. The window follows the drag directly, including in focus mode. Its status comes from the booted device and available framebuffer; the runtime name supplies the OS version. Moving the capsule never sends touches. Only an attached inspection panel follows the device; independent panels keep their positions. The complete window fits the destination display after a move.
- **Size and window lifecycle:** drag the visible lower-right grip outside the LCD, or choose 50/75/100% in the capsule’s **기기 메뉴**. The same menu offers center, minimize and close. Close does not shut down the simulator. Call `window` again to reopen; the Dock restores an existing LCD, including minimized windows. The menu bar/LCD menu also exposes each device menu.
- **Right toolbar:** Home, clockwise 90° rotation, Fold (foldable models only), Capture, Record, Lock and More. Rotation and hinge motion are serialized in the backend and block duplicate clicks while transmission/motion is unsafe. A successful local rotation send immediately updates host presentation; passive guest confirmation no longer keeps controls disabled. A later intentional turn resolves from the last delivered request, including while the guest is still catching up. On Duo, each turn rotates the live device pixels and model mask in mac-cu even if the guest app keeps its portrait layout. Guest orientation requests still use the device's HID control; the UI separately reports visible device rotation and observed app rotation. Pointer coordinates, accessibility boxes, captures/guides, resizing and previews follow the same presentation. An unknown initial closed pose uses the currently shown portrait reference and says so; the cover's rot0 is not physical-pose evidence. The explicit host pose survives folding, app layout changes, LCD close/reopen and input reconnection for the running daemon. Other apps' orientation requests do not override that host pose; use More's explicit orientations to align it. A daemon restart starts from guest readback. More includes Siri, side button, explicit orientations and model-specific Crown controls. Only implemented actions are listed. Unsupported models omit Fold/rotation as appropriate, and unresolved recording targets report a reason.
- **Fold:** one slider in a native popover. Click its integrated 0°/90°/180° labels for exact angles; drag for any whole degree, including 89° beside 90°. Arrow keys change 1°, Shift-arrows 10°, Home/End select 0°/180°, and Page Up/Down select major ticks. The confirmed angle remains separate from the selected draft. Failed drafts survive readback; Return/Space or the accessibility value/press action retries the exact selected angle. The slider is one focus stop with numeric accessibility value/actions.
- **Completion/readback:** `rotate` and hinge setters return after local delivery or the safe continuous trajectory and endpoint hold. Structured `rotation`/`hinge` results mark `delivered` and `confirmationPending`; these are not claims of observed guest state. Read `hinge` without a target for the actual angle/active screen, or use `screenshot`/`describe` for current guest content. A repeated hinge target skips motion only when this request freshly observes both the angle and a consistent active display. The LCD observes display and angle independently with bounded, cancellable per-device readers. New intent, failure, reconnect and close revoke earlier observations. Pointer admission waits for coherent geometry after motion; input releases remain ordered.
- **Capture and recording:** Capture uses the existing active-display screenshot backend and native JPEG save picker; “Saved” follows a successful write. Recording uses the exact active guest screen and a native movie save picker; its native video keeps guest orientation rather than the host-only presentation turn. It becomes active only after the recorder reports the first frame. Stop finalizes the owned recording process; errors and incomplete files remain visible. Closing the LCD stops its recording without affecting other devices.
- **Bottom toolbar:** Input opens text, key and clipboard actions plus Mac keyboard forwarding. Touch toggles viewer markers directly (they never enter captures). Environment applies appearance, contrast and text size through simctl and reads the setting back. Location validates latitude/longitude and offers clear; command acceptance does not assert observed guest movement. Inspection opens screen-element search, wait/tap/press, UIView and 1–3 finger controls, guided capture, and activity/results. View exposes focus, sizes and window lifecycle. Narrow toolbars scroll instead of shrinking targets.
- **Inspection panel:** the existing inspection controls, drafts and activity owner move into a separate panel only when requested. Basic device/fold/input controls remain in the LCD toolbars, avoiding simultaneous stale controls. Inspection retains per-device detach/rejoin and layout recovery. Previous sidebar layout preferences are preserved; inspection uses a separate preference namespace.
- **Scope:** proposed audio, software-keyboard, biometric, GPX, logs and system-management entries are not added as inert native placeholders. Management and API settings open their existing separate windows. Clipboard paste and UIView inspection retain their consequence confirmations; no destructive system operation was added.
- **Focus:** choose **집중 모드** in the device menu to hide the right/bottom toolbars and all detached inspection panels. The capsule and its menu stay visible for movement, restoration, sizing and closing. **⇧⌘T** continues to reveal advanced tools and exits focus mode. Draft fields survive these changes.

Clicks, drags, Option-drags, scroll and keys in the LCD retain the existing HID path. Chrome and transparent margins are separate hit targets. Manual contacts and held keys are released on focus changes, resizing, screen changes and close. Guest input coordinates use AppKit points regardless of Retina scale, with the simulator’s model mask and actual rotation. Reduce Transparency uses solid surrounding controls, Increase Contrast strengthens outlines, and Reduce Motion disables custom spring/fade feedback. Periodic refresh coalesces with bounded operation observations; no unbounded poll queue is created.

Preview restoration, per-display stacks, occlusion detection and device shutdown use the existing lifecycle. Build/log/web inspector features remain in their existing tools. For development verification without replacing a user installation, see `docs/mac-cu-device-window-validation.md` in the source repository. Development evidence is excluded from Plugin mirrors.

Open **설정…** from the menu bar, or **판단 API 설정…** from a device or toolbar menu, to configure OpenAI Decisions. The settings window uses the daemon environment and Keychain, never a previously connected client’s key. Its connection check sends only synthetic text; actual screen evidence is sent only for requested judgments.
