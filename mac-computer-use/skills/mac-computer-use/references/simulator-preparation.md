# Prepare simulators from mac-cu

Open **시뮬레이터 관리…** from the mac-cu menu bar or application menu. This is the native preparation UI; app builds, test app installation, launch and logs still use Simulator Pilot and the target project's build instructions.

The window has three persistent tabs: **기기**, **새 기기**, and **런타임**. Result, cancel, readback recovery and **상세 로그** remain outside the tab content. Each page scrolls independently on a compact desktop. **런타임** lists installed/available counts, build, compatibility and the selected runtime ID above its installation controls.

- **Installed devices:** **기기** shows names, OS, actual state and live Simulator Pilot usage records. Search by name, UDID, OS or state and choose all/available/booted devices. The adjacent selection panel exposes the full UDID and runtime ID beside the state-appropriate action; a checkmark and text identify the selected target. Hiding a selection with a filter clears it rather than redirecting its action to another row. No devices exposes **새 기기 만들기**; no matching devices exposes **검색 조건 초기화**. Counts appear only after inventory readback. **새로고침** reads Xcode again; the existing board refreshes an idle device page without interrupting a text editor or creation/runtime page. No extra polling timer is created.
- **Start / LCD:** **실행 및 LCD 열기** boots only a shut down, available device, waits for completion and verifies the same UDID before opening the existing native LCD. A device already booting offers **부팅 대기 및 LCD 열기**, which waits without a duplicate boot. **LCD 열기** on a booted device does not reboot it. A live claim blocks these actions and names its usage record beside the disabled action; coordinate with the owning session first. The UI never forces a claim or shuts down another device.
- **Create:** **새 기기** presents a labeled name, OS runtime and compatible model in that order. Invalid names disable **기기 생성** and show an inline reason; no runtime exposes **런타임 관리**. Runtime IDs distinguish specialized images such as Duo from general iOS with the same display name. The type menu shows supported model names and IDs. Confirmed creation switches to **기기** and selects the new UUID without booting it, clearing filters only when needed to reveal it. A failure retains the creation page and draft. **목록 다시 읽기** inspects current state and does not repeat a failed create.
- **Download:** select iOS, watchOS, tvOS or visionOS, then **런타임 다운로드…**. Confirm the platform and potentially multi-GB download in the native dialog. Xcode chooses the runtime offered for that platform. The result confirms an available platform runtime, including one already installed; it does not claim a new version was necessarily added.
- **Import:** **DMG 가져오기…** selects a local Apple simulator runtime DMG for installation. Success requires a newly available runtime or changed build in the inventory. If no change is detected, the UI explains that the image may already be installed rather than claiming a new installation.

Installation uses Apple's `xcodebuild -downloadPlatform` and `-importPlatform` paths. See [Apple's component installation guide](https://developer.apple.com/documentation/xcode/downloading-and-installing-additional-xcode-components). Full Xcode is required; the manager shows failures and an official Xcode installation link without changing the active developer directory or bypassing licensing, login or administrator requirements.

Long operations show a spinner, bounded recent output and a cancel button. Closing the manager requests cancellation; reopening waits for that operation to stop before accepting another. Cancellation and timeouts terminate only the operation's child process group. Already installed runtimes, created devices and booted devices remain. Refresh the inventory after cancellation or failure to inspect actual state. Closing an LCD still follows the existing LCD lifecycle and does not shut down its simulator.

For agent-driven device interaction, keep the selected UDID and follow Simulator Pilot's claim/release rules. The manager shows usage records but does not claim devices on behalf of an agent session.

Keyboard route: task tabs lead to search, the new-name field or the installed-runtime list. In creation, Tab from the name editor focuses the runtime picker, then the compatible model picker; Shift-Tab returns to the preserved name. Space/arrows operate native popup menus. Return in a valid name field creates a device. The download confirmation initially selects cancellation and Return cancels; closing a download/file dialog returns to its initiating control or the active job cancellation control. Programmatic AppKit checks cover Tab/Shift-Tab field routes, Control-Tab/Control-Shift-Tab wrapping and native confirmation Return cancellation/focus return without executing an install. Physical popup-menu operation, Escape/file picking, VoiceOver and touch remain separate checks.
