# AGENTS.md

- MacPilot MUST NOT depend on third-party libraries, including libraries copied into the repository. Use project-owned code, standard libraries, and frameworks supplied by the operating system or Xcode.
- Modify the canonical `mac-computer-use/` and `simulator-pilot/` packages directly; both marketplaces point to these directories. There is no `plugins/` mirror.
- Use the skill-creator workflow for material skill changes. Keep trigger wording consistent across SKILL.md, manifests, UI metadata and README.md; keep long guidance in references/.
- Preserve manifest-relative setup resources, original attribution, user profiles, Keychain entries, captures and simulator data.
- Do not include credentials, private service configuration, generated executables, browser profiles or local development evidence in Git or release archives. Do not reproduce removed identifiers in docs or commit messages.
- Run `python3 scripts/validate_distribution.py` and native checks appropriate to changed functionality. Document actual checks and remaining limits. Run foreground desktop checks serially on an unlocked desktop and keep input guards.
- Before launching any native test/preview app, follow [native check safety](docs/native-check-safety.md). Preserve production helper argument dispatch, reject inherited test entry, and prove these routes without opening the GUI first. Launch through a parent watchdog with a deadline, an exact executable instance budget and cleanup on failure/interruption. A unique bundle ID alone is not process isolation. Stop and clean the owned test processes immediately on duplicate icons/windows or unexpected relaunch; do not retry until the guard checks pass.
- Update CHANGELOG.md for user-visible changes. Version both host manifests together; update marketplace versions and README.md when releasing a package.
- Before handing back completed implementation work, build and replace the global mac-cu app from the validated canonical source and restart it so the user can verify the result. The user has given standing authorization for this local installation; do not ask again. Back up the previous app, preserve its bundle/signing identity, Keychain entries, permissions, profiles, captures and simulator data, and verify the running version and UI. Keep this completion install separate from isolated development checks and from Git/marketplace publication.
- Commit/push/publish only within the user's authorized scope. Verify remote main, tags, release asset hashes and catalog content after publishing. Keep local installation separate from marketplace publication and fresh-session exposure.
