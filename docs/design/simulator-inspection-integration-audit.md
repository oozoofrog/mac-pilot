## Decision inputs

Keep the existing AppKit LCD surface, toolbar, HID and window ownership. Prefer a linked native inspector window for captured hierarchy, 3D navigation and property editing. Keep LCD AX picking in the existing inspection region. This is a design recommendation, not an implemented capability or approval to migrate the host to SwiftUI. `docs/design/swiftui-assessment.md` remains an input for optional hosting of inspector controls.

The editing feature requires a separate typed mutation protocol and live target revalidation. A captured object address alone cannot safely identify a later edit target. Do not enable general capture, UIKit LCD polygons or editing merely because the portrait fixture passed.

## Candidate shared contracts

Introduce a capture envelope shared by outline, 3D and details: schemaVersion, captureID, target PID/start seconds+microseconds/resolved executable/device, display/screen identity, capture time and interval, operation generation, cleanup/recovery status and independent capability flags. Carry source space and units for every geometry field. Preserve original properties, missing values and unsupported reasons.

Flatten hierarchy once into nodes keyed by `(captureID, objectID)`, with parent, siblingIndex, depth, preorder and subtree range. Keep ordering deterministic and reject cycles/duplicate IDs. Selection stores that key; search filters visibility without selecting a first match. If a selected node is filtered out, retain its detail with a visible hidden-by-filter status or clear explicitly. Across new captures clear selection unless a separately validated semantic match is presented for explicit reselection; addresses can be reused.

Geometry needs ordered four corners in fixed space, bounds, window/screen identity, orientation and scale. LCD projection needs an explicit fixed→guest→host→viewport mapping, current backing/letterbox/mask revision and presentation generation. AX rectangles keep their existing guest path. Never send fixed-space UIKit polygons directly through `presentingGuestFrame`. For 3D, name `explosionDepth = hierarchyDepth × userSpacing` separately from actual layer transform, anchor, zPosition and perspective; unknown physical Z stays unknown. Start with untextured wireframes if snapshots/clips are absent. A full-screen screenshot is not independent per-view texture.

Editing contract proposal: `(operationID, captureID, targetIdentity, nodeKey, property enum, typed proposedValue, expectedOldValue, generation)`. Server owns the allowlist and code templates. Candidate first properties are UIKit alpha (finite 0…1) and hidden (Bool), contingent on backend experiments; AX value editing requires confirmed settable attribute semantics and a dedicated typed setter, not AXPress or text typing disguised as editing. Capability flags must disable unsupported fields with a reason. Raw KVC paths, selectors, LLDB expressions and source text are excluded.

Before mutation, revalidate process lifetime/front app/device/display and object membership/type on the validated main thread. A fresh bounded hierarchy membership check cannot by itself exclude same-process address reuse; a separately verified object-lifetime mechanism is also required. Read expected old value immediately before set; conflict fails without write. Return before/requested/readback values, target identity, timestamps, detach/recovery and per-step status. Success requires observed readback plus cleanup, not setter delivery. Runtime changes are transient and may be overwritten by app layout/state. No source persistence is implied.

Revert is a new explicit guarded mutation with expected current value and stored old value. It can fail if the object disappears, app changes the property or target exits. Timeout after write returns outcomeUnknown, disables blind retry, and requires readback reconciliation. Do not promise rollback after target loss or debugger failure. Do not auto-revert on window close against a stale address. Preserve an edit receipt and show failure/recovery beside the selected property.

## UI ownership and acceptance routes

A linked native window provides space for tree/search, 3D canvas and property panel without replacing the compact rail or stealing LCD gestures. Key it by device/display and capture, not the latest open device. Closing cancels owned work and waits for backend cleanup without forcing the window to remain interactive. Losing focus releases held LCD input. Reconnect or target change marks captured content stale, disables mutation and clears LCD overlays; browsing historical geometry can remain available with a persistent captured/stale label. A failed capture must not present the previous tree as new success.

An embedded LCD 3D region is possible but requires a distinct mode switch, guest HID suspension, orbit-versus-pick routing, Escape restoration and constrained detail layout. It adds surface/input regression scope. Recommend the separate window initially; allow its selection to highlight LCD only after that mapping capability is independently validated. Keep a visible “Open 3D inspector” entry beside capture controls. Opening alone does not capture or attach.

| Goal → state → visible route | Required observed result / recovery |
| --- | --- |
| LCD AX pick/action/edit | Read → loading → explicit pick → LCD click lists candidates → user selects → separate Tap or AXPress. A separate value field and Apply appears only for proven settable attributes. Verify action/readback on the same target; stale or unsupported values show Refresh and no write. Current AX edit backend is missing, so edit acceptance cannot be waived by press/tap success. |
| Capture → 3D exploration | Explicit Capture → progress + Cancel → cleanup-complete snapshot → tree/search → explicit row or mesh selection → synchronized detail. Orbit drag and zoom affect only host scene; labeled Reset camera and depth spacing controls remain keyboard reachable. Captured timestamp and stale state remain visible. Empty capture and no search matches have distinct messages. |
| Supported edit/readback/revert | Select node → inspect original value → change typed draft → Apply → pending → confirmed readback or outcomeUnknown → explicit Revert → confirmed old value or conflict. Invalid input never starts backend. Pending edits prevent conflicting operations; selection changes preserve a clearly targeted draft or require explicit discard. No source-save control. |
| Keyboard and focus | Tab from search into tree; arrows navigate, Return selects/details only. Tab into value and Apply; Space activates focused buttons. Escape cancels pick/draft dialog before closing inspector. Closing returns focus to invoking host control, not automatically to guest HID. For 3D camera provide labeled rotate/zoom/reset controls in addition to gestures. |
| Noncolor/accessibility/narrow layout | Selection has checkmark/row state and named node; pending/error/stale use text. VoiceOver reads target, capture status, selected node and edit result in order; avoid duplicate hosting elements. Narrow panels scroll details without hiding Apply/Revert state. Reduce Motion disables animated explosion/orbit transitions; depth remains directly adjustable. |

## Non-overlapping implementation partition

Agree on typed envelope/operation/capability schemas before workers edit shared files. Suggested boundaries (future allocation, no assignments made here):

1. **AX backend owner:** `SimulatorAccessibility.swift` plus new AX-specific tests. Implements lifetime-aware selection token and supported typed AX value capabilities/set/readback. Supplies backend functions to integrator; does not edit Simulator.swift or Toolbox.
2. **Capture/edit backend owner:** `SimulatorViews.swift`, `SimulatorViewHierarchy.swift`, `scripts/view-capture/` and capture fixtures/tests. Owns target lifetime, debugger safety, typed UIKit mutation/readback/revert and structured errors. General-app admission remains gated until experiments pass. Does not edit host input/rendering.
3. **Inspector UI owner:** new dedicated inspector model/controller/renderer files and new model tests. Consumes frozen contract; owns flattening, selection/search, camera/depth, properties/drafts and state feedback. No direct transport/private API calls.
4. **Lead integrator:** exclusive edits to `Simulator.swift`, `SimulatorToolbox.swift`, `SimulatorWindow.swift`, setup/check scripts and shared docs/manifests. Wires backend dispatch, target invalidation, LCD polygon mapping and linked window lifecycle. Owns any touched existing UI-state/live tests. This avoids simultaneous edits to the current monolithic Toolbox.
5. **One serial validation/install owner:** owns foreground lease, native preparation, evidence receipts and final local replacement. Backend/UI workers supply headless cases and exact expected postconditions; they do not launch parallel GUI checks.

## Validation plan and experiment blockers

Headless first: retain existing UI-state, hierarchy, transport and native safety regressions. Add contract checks for malformed geometry/nonfinite values, duplicate/cyclic hierarchy, limits, deterministic flattening, no automatic selection, filter retention, generation supersession, close/cancel and old completion suppression. Exercise reconnect, PID reuse/path/device mismatch, same-process node replacement, missing/ambiguous AX rows, unsupported setters, expected-value conflict, timeout before/after write, readback mismatch, failed detach and revert conflict. Fake transport must assert zero setter calls after admission failure and no automatic mutation retry. Verify independent AX rect versus fixed polygon transforms at all four rotations, letterboxing, backing scales and screen switch; synthetic checks do not prove LCD pixels.

Required existing checks after implementation: `python3 scripts/validate_distribution.py`, `scripts/check.sh` and changed-functionality native checks. `check-view-capture.py` includes compilation and isolated command dispatch; it is not live LCD evidence. Use `check-view-capture-geometry.py` for saved-data replay when geometry changes. No tests/build were needed or run in this documentation task.

Before **any** native test/preview launch: inspect all current-binary helper/relaunch routes; use `native_check_support.py` dispatch; reject inherited test entry and unknown args with exit 64; preserve production screen-recording helper. Run helper/rejected/inherited guards headlessly under parent watchdog, then native safety regression suite. Declare deadline and exact executable budget, use a unique output directory, and clean only owned executable instances/process group on failure. Stop immediately on duplicate windows/icons. Unique bundle ID alone is insufficient. Never replace global app for an isolated check.

Then one foreground owner on unlocked desktop: claim the existing selected device and verify identity/input counters. Capture a static controlled fixture, open actual LCD, compare rendered landmark pixels and outlines at portrait/landscape/host-only rotation/backing scale; test mask/letterbox, clipping and rotation-in-flight rejection separately. Record captured image versus actual rendered window and timing. Prove no touch/key leakage while pick/search/edit/orbit owns focus, held-input release, Escape/focus return, close/reopen, screen/app switch and reconnect. Capture a fresh hierarchy then exercise tree↔3D selection/search/depth/orbit; report hierarchy explosion separately from any tested physical transform/perspective. For alpha/hidden and supported AX value, verify before→Apply→guest readback→visible effect→Revert→readback/visible restoration, including app overwriting the value and cancellation after delivery. An edit feature is incomplete until its supported runtime route is exercised.

Blocking experiments: API researchers must establish actual supported AX setters and allowed UIKit mutation mechanics; current source has neither. Need bounded general-app capture/recovery beyond fixture, object-liveness strategy across capture/edit gap, clipping/texture source and budget, multi-window/screen identification, and renderer choice under current SceneKit deprecation. Do not turn an undocumented symbol observation into admission. Full SwiftUI declaration/state graph or persistent source edits remain outside current collector capability.
