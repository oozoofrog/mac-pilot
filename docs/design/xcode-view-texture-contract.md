Since non-exclusive behavior and resource allocation are not established, use a fixture with only a few tiny views and retain existing 16 MiB serialized response cap and attach/deadline/recovery guards. ## Response and visual semantics

`+[DBGImage(JSONSerialization) valueWithEncodedValue:format:error:]` at `0x12a1c–0x12c9c` has a dictionary branch for format `image`; it invokes `DBGDecodeValueFromJSONCompatibleValue`, reads `imageData` and `metadata`, and creates `DBGImage` with the `UTTypePNG` identifier (`0x12b50–0x12c34`). Other branches use `dbgDataValue` and type identifiers. This is evidence of a host decoder branch, not proof that the raw wire dictionary directly contains unencoded PNG or that every image uses PNG. Asset-manager lookup and exact response-to-node join remain unresolved; the class symbol alone does not establish the association. Inspect a response's property name, value format and encoding before designing a decoder. Require exact same-capture ID joins, reject duplicate/unknown IDs and absent or incompatible fields, and never infer a join by order.

`snapshotImage` solo/self versus subtree/composited content is **unknown**. The draw-hierarchy variant may include descendants or effects; that is also **unknown** here. Encoded presentation layer is not proven to be an independently drawable image. `visualRepresentation` is a separate unresolved representation, not an alias. Effects, masks, clipping, alpha, layer compositing, affine/perspective transforms and image pixel scale are distinct unknowns. Geometry's fixed-coordinate points and screen scale do not prove image bounds, orientation or pixels-per-point. A screen screenshot is only a composite reference; never paste it on every plane or hide/unhide arbitrary subviews to synthesize textures.

For a subsequent owned fixture, compare a parent with a distinct child, overlapping translucent siblings, clipped content, mask, effect, affine and perspective cases, and known pixel-scale markers against the original composite. Establish which pixels belong to self and descendants before assigning per-plane textures. Effects and unsupported surfaces may require a composite fallback; do not claim independent fidelity without evidence. Test each variant separately and preserve raw request/response and capture identity. Review the result before adding layer or effect requests.

Candidate decoder limits for that experiment: at most 64 selected nodes, 1024×1024 pixels per image, 4 MiB encoded per image, 16 MiB aggregate encoded and 32 MiB aggregate decoded RGBA, with dimensions and multiplication checked before allocation. These are proposed host-side limits, not target-side protections. Decode only recognized formats; reject malformed, decompression-bomb, oversized or duplicate assets. Surface unavailable/partial texture status and retain an outline-only inspector; do not silently label missing or composited images as independent layers. Runtime capability, UI fidelity, edits and production deployment remain unproven.
