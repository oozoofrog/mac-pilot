# SwiftUI resident capture backend

The normal inspector capture carries `inspectionScope` from `SimulatorInspectionHost.prepare`. The coordinator freshly reads boot identity, runtime metadata, active display/presentation, front PID and native target lifetime before and after the backend operation. Cached scope equality remains an additional consumer fence. This implementation does not launch, terminate or prepare a guest app.

`SwiftUIBridge.swift` is the generic `_UIHostingView` protocol adapter. `native_build.py` compiles its object and the existing MRC resident into one signed, pinned image. Build provenance includes Swift compiler/version, SDK, SwiftUI interface, source and image hashes. Existing exact toolchain/runtime/debug-entitlement admission, reservation, quarantine, exception, pool/context and terminal receipt rules remain in force.

The retained registry traversal identifies supported hosts by typed conformance. Each admitted host first supplies a `drawHierarchy(afterScreenUpdates:false)` composite, then raw serialized graph bytes on the normal untraced main callback. Capture-local registry tokens and scene identifiers bind both outputs. Final traversal rechecks class, parent, window, scene, hidden/alpha and registry association. Stages have separate monotonic intervals, including bounded encoding; they are not an atomic snapshot.

The resident bounds the host list to 64 entries and admits at most eight hosts. The production-used `swiftui-scheduling.h` checks cancellation and the same monotonic two-second start-admission budget before each stage. It never resets the clock between stages or hosts. An admitted nonpreemptible call can finish after the deadline; its recorded interval includes that overrun, and no subsequent stage starts. Rendering preflight refusal or a rendering exception does not suppress a graph call while time and cancellation permit. Graph and rendering exceptions and intervals remain independent. Encoded graph data shares a separate 4 MiB allowance; graph and PNG strings share 8 MiB. Individual PNG bytes are limited to 2 MiB. Existing 4096-pixel dimensions and texture estimates apply. Combined response preflight can omit the old UIKit texture hierarchy to stay within the unchanged 16 MiB transport limit. Call-internal allocation and nonreturning private framework calls cannot be preempted; the existing pending/quarantine lifecycle remains necessary.

`swiftui_product.py` passes bytes through the canonical bounded parser and consumes aggregate graph node, JSON value and reflected-attribute allowances. It preserves actual children, UInt32 property IDs and opaque attributes. IDs are capture-local and grant no mutation authority. Empty and nil graphs explicitly require recording preparation. No restart action or recording preference is inferred.

The Swift snapshot normalizer joins composites to hosting nodes, removes their previous self assets and applies shared encoded/pixel/count budgets. The final snapshot follows `swiftui-product-integration-contract.md`. Old UIKit-only results remain supported. Contradictory joins or sections fail with the returned cleanup receipt retained by the wrapper.

Headless tests live in `tests/swiftui-product-backend/`. The Python suite exercises topology, outcomes, scope drift, joins and aggregate budgets. The guarded console runner compiles frozen inputs and checks composite asset joins, legacy UIKit, malformed sections and typed scope validation. The Foundation-only `run-scheduling.py` executes the actual production scheduler with controlled clock/cancellation and bounded fake native callbacks. It covers the observed 2.898-second graph, visual-first order, both admitted outputs, expiration between stages and hosts, cancellation, invalid rendering preflight with a valid graph, and independent exceptions. All native console entry points are guarded and run under a parent watchdog with one exact executable instance. These tests do not access a guest. Archived raw graphs can be supplied privately as parser data; archived identity is never live authority.

Product live qualification remains required for current boot joins, stale consumer rejection, actual prepared-app capture, renderer behavior, and lifecycle/cleanup. Source compilation and offline parsing do not establish those results.
