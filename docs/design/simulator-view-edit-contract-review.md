# Simulator view identity and edit contract review

Independent review, 2026-11-09. **Preferred experimental mechanism: a target-side, capture-scoped zeroing weak registry, resolved through fresh reachable-view traversal.** Keep edits disabled until the gates below pass. Associated per-view nonces are a credible alternative for normal Objective-C object destruction, not a demonstrated runtime capability or a security boundary. An inspection-long paused transaction is not the default when a finite registry operation can work.

This review changes only this document. No GUI, LLDB attachment, Simulator mutation, production build, restart or installation was performed. Existing dirty work is preserved. The proposed schema is separate from the existing schemaVersion 1 capture protocol; it does not silently enable that protocol's fixture-only routes.

## Evidence and consequential findings

Current Apple documentation confirms that association values can be set, retrieved and individually cleared with nil; the policy determines value ownership. Atomic association operations do not make a hierarchy traversal or property edit atomic. `ASSIGN` is unsafe-unretained, **not zeroing weak**. Sources: [set](https://developer.apple.com/documentation/objectivec/objc_setassociatedobject(_:_:_:_:)), [get](https://developer.apple.com/documentation/objectivec/objc_getassociatedobject(_:_:)), [policies](https://developer.apple.com/documentation/objectivec/objc_associationpolicy), [atomic retain](https://developer.apple.com/documentation/objectivec/objc_associationpolicy/objc_association_retain). Current DocC Markdown versions were fetched directly because the web reader rejected `text/markdown`.

The [retired Associative References chapter](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/ObjectiveC/Chapters/ocAssociativeReferences.html) describes unique pointer keys, value release on owner destruction and the danger of clearing other clients' associations. It is historical context, not proof of a current Simulator runtime. Independently, Apple's published objc4 source at commit `fb265098298302243cd7eeaa1f63f0ba7786dd9a` removes associations during object destruction before freeing the object; its association implementation retains values and removes the map entries. This supports the normal-lifetime inference that a new object at recycled storage does not inherit the destroyed object's association. It does not establish which objc4 build the selected Simulator ships. Sources: [destruction](https://github.com/apple-oss-distributions/objc4/blob/fb265098298302243cd7eeaa1f63f0ba7786dd9a/runtime/objc-runtime-new.mm#L9428), [associations](https://github.com/apple-oss-distributions/objc4/blob/fb265098298302243cd7eeaa1f63f0ba7786dd9a/runtime/objc-references.mm#L159).

That source also exposes two material qualifications: setting an association can fatally reject a class that forbids associations, and first association can invoke `_noteAssociatedObjects`/initialization work. Catching Objective-C exceptions does not contain a fatal abort. Per-view instrumentation is therefore not a pure read and cannot be advertised as side-effect-free. No private class-flag probe is proposed as a universal safety check.

Lookin's actual identity path is a useful precedent, not an external-debugger safety proof:

- [`NSObject+LookinServer.m`](https://github.com/QMUI/LookinServer/blob/ae396132ce6494477457cf450116dc760518d8ad/Src/Main/Server/Category/NSObject%2BLookinServer.m) registers an object once and stores its numeric OID through its associated binding dictionary.
- [`LKS_ObjectRegistry.m`](https://github.com/QMUI/LookinServer/blob/ae396132ce6494477457cf450116dc760518d8ad/Src/Main/Server/Others/LKS_ObjectRegistry.m) appends the object to `NSPointerArray weakObjectsPointerArray`; the OID is its nonzero array index. Lookup checks the index and retrieves that entry. It does not cast a saved address into a live object. There is no compaction or bound in this implementation; copying it would not meet our bounds.
- [`NSObject+Lookin.m`](https://github.com/QMUI/LookinServer/blob/ae396132ce6494477457cf450116dc760518d8ad/Src/Main/Shared/Category/NSObject%2BLookin.m) uses a static key in its resident compiled image and retained binding dictionary. That static-address pattern must **not** be copied into unloadable LLDB expression code.

### Required research fixes and retained boundaries

| Finding | Consequence and concise correction |
|---|---|
| PID/start/path/capture ID plus address/class/parent is insufficient | Keep the research's correction. Replacement at the same address requires a zeroing weak reference or object-bound generation, not more address metadata. |
| “Unforgeable generation token” overstates in-process trust | Replace with unpredictable capture-scoped token for accidental stale-reference protection. App code can inspect/replace associations, swizzle accessors, falsify traversal or corrupt memory. Neither proposed registry nor nonce is secure against a malicious inspected process. |
| Identity design omitted stable target storage and bounded cleanup | Specify the anchor/key, ownership checks, host and target state, release semantics and limits below. A UUID alone supplies none of these. |
| Main-thread check is necessary but insufficient | Debugger injection may interrupt a main-thread UIKit critical section. Require a tested safe-entry policy; do not equate `[NSThread isMainThread]` with reentrancy safety. |
| Current address join is valid only within observed capture boundaries | `collect.expr` calls the private hierarchy collector and then separately walks windows. It does not hold a verified common object generation across both phases. Never grant edit authority from private `objectID`; use the registry traversal as the authoritative editable-node model. A stale/missing join is read-only. |
| Per-view textures are absent | Keep this limitation. Require an actual node/layer image and provenance, including whether descendants are included. A screenshot crop can include occluders; a full composited screenshot repeated on planes is not per-view texture. Parent subtree textures plus child textures can double-render descendants. |
| Exploded hierarchy depth is not physical Z | Keep separate fields for synthetic separation, sibling order, layer zPosition, model/presentation transform and unknown values. Do not infer one from another. |
| UIKit backing views do not recover SwiftUI declarations | Keep explicit UIKit scope; no inferred modifier/source graph. Runtime changes can be replaced by SwiftUI reconciliation. |
| Console mutation does not prove Xcode inspector editing | Research already states this correctly; retain it. The corrected `@"%@"` expression matches raw `DebugHierarchyKit-strings.txt:938`. No remaining correction to that template is needed. |

Local evidence reviewed: `scripts/view-capture/{capture.py,collect.expr}`, `mac-cu-src/SimulatorViews.swift` under the canonical skill, completed `xcode-view-debugger-research.md`, team plan, native safety instructions and narrow raw files in `/tmp/mac-pilot-view-research.sZQeuVlr`. The collector limits traversal to 20,000 views and response JSON to 16 MiB. It verifies main queue/thread, traps exceptions, unwinds on expression failure, forbids all-thread fallback, and supervises detach/recovery. These are valuable boundaries, not a mutation transaction or rollback mechanism.

## Mechanism comparison and decision

| Mechanism | Identity across resume | Lifetime and cleanup | Decision |
|---|---|---|---|
| Retain selected objects while app remains paused | Retained objects cannot normally deallocate/reuse storage | Changes lifetime; stalls application/UI inspection; deadlines and forced-unwind leaks remain; detached objects must still be rejected | Diagnostic fallback for an explicitly bounded experiment only. Do not hold a user app stopped throughout host UI inspection. |
| Per-capture/node nonce associated with every captured view | Normal destruction removes the old association; fresh traversal obtains a live object before reading its token | Retains token, not view, if payload has no back-reference. Adds runtime state to every view; detached surviving views cannot be cleaned by reachability traversal; first-association side effects | Feasible hypothesis with additional gates. Not preferred for initial implementation. |
| Capture-scoped token → zeroing weak view registry | A weak lookup becomes nil on destruction; a recycled address cannot revive the old weak entry | One bounded registry; no persistent strong views; detached entries can be dropped without dereferencing a view | Preferred. Verify weak-load semantics in actual LLDB compilation/runtime and discard entire capture on uncertainty. |

Use Foundation [`NSMapTable strongToWeakObjectsMapTable`](https://developer.apple.com/documentation/foundation/nsmaptable/strongtoweakobjects()) with object keys/values and documented options, not raw pointers or `ASSIGN`. Apple's [NSMapTable overview](https://developer.apple.com/documentation/foundation/nsmaptable) describes weak lifetime removal. Each capture maps fresh random node tokens to views, including parent and window nodes. Never recycle tokens. Do not materialize a persistent strong dictionary representation of this map.

### Stable key, anchor and ownership

Candidate target storage uses a single association on the process-resident `NSObject` **class object**, obtained afresh by public runtime class lookup on every operation. The key is `(const void *)sel_registerName("org.oozoofrog.macCu.viewInspection.registry.v1")`. This is a fixed internal name, never caller input; it is never invoked as a selector. [Apple documents](https://developer.apple.com/documentation/objectivec/sel_registername(_:)) repeated registration returning the existing selector. This avoids a stack address, expression-local static, NSString literal address, disposable malloc key or unloaded JIT symbol. Prove cross-expression/detach persistence experimentally. The anchor choice remains a gate, not an already validated integration.

The association retains only a Foundation state dictionary, weak map and small scalar/string records. No persistent blocks, custom JIT classes, callbacks or view references. Use `OBJC_ASSOCIATION_RETAIN`; serialize all accesses on the verified main thread and with one host target lease. Atomic retain does not protect mutable dictionary operations or a compare/set sequence. Explicit autorelease scopes and strong local loads are required; LLDB ARC/MRC behavior must be verified rather than assumed.

State contains schema/magic, host owner nonce, target epoch nonce, current capture ID, expiry, busy phase, sequence high-water mark and bounded operation results. Unknown preexisting content, different active owner or shape mismatch is `keyCollision`/`ownershipConflict`; never overwrite or call methods on arbitrary content to “repair” it. Shape checks are accidental-collision defense only. A same-process adversary can spoof even the Foundation objects and magic. Exclusive host ownership does not exclude app swizzling or another debugger; conflicting debugger is rejected before attach.

Release drops the weak map and capture payload, preserving only bounded ownership/sequence tombstones until target exit or a verified owner handoff. Do not remove another owner's state. Never call `objc_removeAssociatedObjects`. A crash can leave this bounded payload resident; host TTL is an authority expiry, not a claim that target memory is reclaimed by a timer. Subsequent authorized entry can clear expired owned state. No persistent target timer is introduced.

For the alternative nonce mechanism, use the same process-stable key principle and an immutable fixed-size payload `{owner, epoch, captureID, nodeToken}` with no view references. Each recapture replaces the payload only after ownership validation; old captures lose edit authority immediately. Cleanup clears only exact owned payloads on currently reachable objects. Detached objects keep inert tokens until deallocation or future reachable cleanup. A per-capture cap alone cannot bound accumulated detached tokens: reserve a conservative lifetime total before assigning, charge failed/uncertain assignments, never refund unreachable objects, and disable further tagging at the cap. Persist that accounting across host reconnects or refuse re-entry when it is lost. Do not allocate a new selector/key per capture or per node. These extra requirements are a substantive reason to prefer the weak registry.

## Exact proposed protocol

All objects reject unknown keys. All IDs are opaque generated UUIDs except the enumerated property and operation kinds; strings have fixed maximum lengths. No expressions, selectors, KVC paths, shell fragments or address fields are accepted. Runtime addresses may occur in private diagnostic evidence only. The host resolves opaque IDs against its own authoritative records rather than trusting caller-supplied identity.

Common request fields:

- `schemaVersion: 2`, `kind: capture|edit|revert|release`, `requestID: UUID`, `inspectionID: UUID`, `ownerID: UUID`, `target: {deviceID: UUID, pid: positive Int32, start: [UInt64 seconds, UInt64 microseconds], executablePath: absolute String, bundleID: String}`, `targetEpoch: UUID|null` (null only for initial capture), `deadlineMs: Int`.
- Host adds internal `leaseID`, `requestDigest` (SHA-256 of canonical validated request), and monotonic deadline. These are not user-editable. Capture creates the epoch only after a verified target/anchor handshake. Responses echo resolved target and IDs, never silently substitute another target.

| Request | Additional required fields | Successful payload |
|---|---|---|
| `capture` | `mode: readOnly|editable`, `replaceCaptureID: UUID|null`, `limits: {maxNodes, maxDepth, maxBytes}` | `captureID`, `targetEpoch`, `capturedInterval`, `expiresAt`, `nodes[]`, `windows[]`, `capabilities`, `registryState`. Each node has `nodeID`, `parentNodeID|null`, `windowNodeID`, `runtimeClass`, `properties: {hidden: Bool|null, alpha: finite Number|null}`, `editableProperties[]`, `unavailableReasons[]`. Editable node IDs are random registry keys, not addresses. Root window has null parent and its own window ID. |
| `edit` | `captureID`, `nodeID`, `expectedParentNodeID|null`, `expectedWindowNodeID`, `expectedClass`, `property: hidden|alpha`, `expectedValue`, `value`, `operationID: UUID`, `sequence: positive UInt64` | `before`, `requested`, `observed|null`, `setterEntered: Bool`, `propertyRevision`, `undoToken|null`, `postcondition: matched|mismatched|unavailable`, `needsRefresh: Bool` |
| `revert` | `captureID`, `undoToken`, `operationID`, `sequence` | Same edit payload. Server derives node/property/original value from its undo record; caller cannot supply a replacement “original.” |
| `release` | `captureID`, `reason: close|refresh|expired|cancel|targetChanged`, `operationID`, `sequence` | `authorityRevoked: true`, `registryReleased: Bool|null`, `remainingOwnedEntries: Int|null`, `residualState: none|tombstone|boundedPayload|unknown` |

Every response also includes `status`, `reasonCode`, `phase`, `operationID|null`, `requestDigest`, `timings`, `mutationOutcome: notEntered|appliedObserved|enteredUnverified|uncertain|notApplicable`, `cleanup: {detach: notAttached|verified|failed|unknown, sameLifetimeRecovery: verified|targetExited|failed|unknown, childrenReaped: Bool}`, `evidencePath|null`. Status values are `success`, `rejected`, `unsupported`, `conflict`, `expired`, `cancelled`, `timeout`, `outcomeUncertain`, `cleanupFailed`, `failed`. Reasons distinguish target/device/front-app/owner/capture/window/parent/class/value changes, weak nil, unreachable view, key collision, reentrancy, bounds, bad schema, unsupported runtime and exception.

A read-only capture does not create editable tokens; a later edit request cannot promote it. An editable capture instruments the target registry and must say so. Missing typed values disable that property's control. Selection chooses among returned windows; no automatic first-window fallback. Textures, when available, need separate `assetID`, `nodeID`, `representation: solo|subtree|layer`, pixel size/scale, alpha format, capture interval and unsupported reason. This schema does not claim texture feasibility.

## Mutation, reversion and invalidation

1. Acquire the existing device/target ownership path and validate target lifetime/front app, capture/epoch/owner/expiry, exact request types and operation ledger **before attach**. `hidden` accepts JSON Boolean only; `alpha` accepts a finite JSON number in [0,1], not Boolean, NaN, infinity or coerced strings. Normalize to target CGFloat precision and retain its round-trip representation for comparisons; no epsilon comparison that could overwrite a distinct app value.
2. Use the existing supervisor/worker/preflight/main-thread selection/detach/recovery path. Verify lifetime again after attach. The entire lookup/compare/set/readback is one fixed internal expression, not separate expressions with app execution between them. No unbounded dispatch_sync, run-loop pumping or all-thread fallback to escape a deadlock.
3. Enter the target operation guard. Reject if busy or if safe-entry cannot be established. Walk current authorized scene/windows and live subviews with strong local references and bounded traversal. Discover the selected object from that traversal, then compare it by object identity with a **strong local load from the zeroing weak map**. Do the same for window and parent. Never reconstruct an object from a saved integer pointer. Nil weak value, detached object, multiple match, wrong class/parent/window, traversal truncation or changed owner/capture refuses the setter.
4. Read the typed getter, compare the exact expected value and recheck reachable ownership immediately before the setter. Getter/traversal methods may themselves execute app code. A reentrant call is refused by the busy guard; a getter or hook that invalidates graph/epoch causes refusal. Supported targets must obey UIKit main-thread ownership and normal runtime memory safety. There is no general isolation guarantee against hostile or racy app code.
5. Record target phase `setterEntering` and reserve the operation result before sending exactly one typed `[view setHidden:...]` or `[view setAlpha:...]`. If before equals requested, record `noChange` without invoking the setter. Keep a strong local reference through getter/readback; no persistent selected-view retention.
6. Read back and recheck identity/parent/window. Store result/undo record only if the expected postcondition remains valid. Detach and verify recovery separately. A readback match proves an observed runtime value, not pixels, persistence or complete side-effect accounting. A fresh capture/visible frame is separate evidence.

Capture, edit and release may themselves allocate or invoke app code. Overridden getters/setters can reenter, mutate other properties, detach the object, schedule work, throw, block or exit. A caught exception after setter entry is not `notEntered`. LLDB unwind, cancellation and timeout do not roll back writes, allocations, busy flags or application side effects. Preserve `uncertain` if entry/completion cannot be established. Never reset a stuck target busy flag and resume edits on the strength of a host timeout alone.

Revert is another explicit one-property operation. It requires the same capture/node weak identity, parent/window/class, valid undo token and current value exactly equal to the last observed applied value; it restores the recorded `before`. Permit only the latest unreverted operation for that node/property revision. Consume the undo token on a confirmed revert; invalidate it on ambiguity. Value comparison cannot detect an app changing A→B→A; report this limitation rather than promising change-history isolation. No automatic undo, multi-property transaction or rollback guarantee.

A capture replacement first revokes the previous host authority and undo records, then releases/replaces target capture state; failure never revives the old capture. Expiry, release, target exit/restart, device/front-app/ownership change, epoch loss, missing registry, timeout/cancel after dispatch, uncertain cleanup or untrusted result invalidates editing and undo. Parent/window/class/value conflict rejects the affected operation and requires explicit refresh. Any uncertain mutation quarantines the inspection; reconciliation may read state but may not infer “never applied” from the present value alone.

Edits affect transient target memory only. App logic, animation, layout and reconciliation can overwrite them immediately. No source/project/persistent model edit is implied.

### Idempotency and bounds

There is no exactly-once setter guarantee across process/debugger failure. The host durably reserves `(targetEpoch, operationID, sequence, requestDigest)` before dispatch; duplicate exact requests return the existing result/in-flight/uncertain status without executing again. Reused IDs with different payloads are conflicts. Target journal marks entry before the setter and terminal state afterward. Sequences at or below the target high-water mark never execute again, even after eviction of a cached result. A missing cached result is `resultUnavailable`, not permission to repeat. Lost host journal/target epoch requires invalidation. No automatic retry, including a new operation ID after an uncertain outcome. A later user-directed change needs a new verified capture and explicitly understood current state.

Proposed initial hard bounds, to be measured rather than silently raised:

- One active inspection and one operation per target; one active capture per inspection. 20,000 live nodes, 512 levels, 16 MiB capture JSON. Enforce limits while collecting, not only after serializing. Truncation may return a marked read-only snapshot but never partial edit authority.
- One weak entry per captured node; token length 36 UUID characters. 256 cached operation results and 256 undo records; evicted undo is unavailable. Bounded host records persist until epoch termination; cap at 4,096 operations per epoch and require a new inspection on exhaustion. Maintain sequence rejection across captures in that epoch.
- Editable capture expires after 120 seconds; no extension by selection or camera use. Expired target state is inert and at most one capped payload; no background cleanup JIT callback. Explicit refresh replaces it. Metadata/text fields each have byte limits and aggregate accounting.
- Keep existing 8-second expression maximum, 45-second work budget, 100-second cleanup budget and outer 160-second host ceiling. Request deadlines may shorten work only; never truncate established recovery budgets or lengthen them from caller input. Host UI inspection occurs after verified detach, with the app running.
- Nonce alternative only: maximum 20,000 assignments per capture and 100,000 cumulative potentially outstanding assignments per target lifetime. Reserve before mutation; uncertain cleanup gets no refund. This is a candidate limit, not a memory measurement. Registry design avoids this accumulation.

## Required experiments and enablement gates

No experiments in this section were run for this review. Headless source contracts alone do not enable Simulator edits.

**Gate A — headless Foundation/Objective-C lifetime harness.** Use a standalone CLI with Foundation, ARC and an explicit autorelease pool; no AppKit/UIApplication launch, LLDB or Simulator. The parent watchdog still bounds duration and owned process count. Prove: weak map becomes nil after final strong reference release; token retains no view; live detached object is rejected by a simulated root graph; dropping a capture frees registry keys; normal associated token dies with its owner; clearing our association preserves a third-party association. Exercise at least two separately loaded/unloaded test code modules resolving the registered selector key to the same value, with state surviving their unload and no persistent callbacks.

Force a deterministic same-address lifetime transition in an isolated CLI fixture using supported Objective-C construct/destruct-instance APIs on adequately allocated storage, with correct destruction and weak cleanup. Keep a separate ordinary allocation/deallocation stress test. If the deterministic fixture cannot be implemented correctly, report it as blocked; a mock pointer equality test or a stress run that never reuses an address is not a reuse proof. Check old weak entry nil and old association absent before registering the replacement, including same class/parent/value cases. This establishes Objective-C behavior, not UIView compatibility.

Test collisions, missing/foreign registry, recapture, expiry, 20,001 nodes, depth/byte limits, duplicate operation IDs, digest conflict, journal eviction/high-water rejection, interrupted host reservation and release idempotency. A CLI fake-view setter must cover counter-based exactly-one invocation, reentry, detach/reparent, throw-before-write, write-then-throw, changed readback and simulated lost response. Verify no automatic retry and explicit uncertainty. Include alpha boundaries, Boolean-vs-number, nonfinite values and round-trip equality.

**Gate B — protected owned-Simulator key/weak/safe-entry experiment.** Only after headless native dispatch safety tests and helper/unknown/inherited-entry checks pass, claim one owned fixture/device, exact executable instance budget and parent watchdog; run foreground checks serially with input guards. Preserve all existing capture preflight, worker, supervisor, detach and cleanup routes. Do not replace production to run experiments. Record host/Xcode/runtime/source hashes and process lifetime. Prove the class anchor/key and weak map survive distinct LLDB expressions, detach/resume/reattach and expression JIT disposal. Measure ARC/MRC local lifetime and autorelease cleanup under success and interrupted evaluation. No SDK added to a general app may be implied by an app-owned fixture helper.

A main-thread safe-entry strategy is a **blocking unknown**. The fixture should expose a known idle/checkpoint oracle, then test arbitrary interrupted UIKit/layout stacks as rejection cases. If no bounded general-app safe-entry predicate can be justified, expose edits only for the validated cooperative checkpoint capability and keep arbitrary-app editing unsupported. Do not infer safety from main queue name, frame validity or a passing static fixture.

**Gate C — actual UIView identity/edit failures.** Prove real deallocation and observed same-address replacement on the owned runtime, while old capture tokens still exist. If reuse is not observed, record the missing coverage. Test detach/reattach, window/scene/parent changes, recapture, process restart/PID reuse, value drift, weak nil, host restart, cancellation before/after setter, exception after write, nonreturning setter, target exit and detach failure. Verify app running/untraced recovery, owned children reaped and unrelated processes preserved. Successful recovery does not turn an uncertain edit into success. An unrecoverable/leaking/hung entry keeps that route disabled; no blind retries.

Then prove `hidden` and alpha 0/0.5/1 on ordinary and overridden UIView setters with target-side counters, typed readback and separately observed visible outcome. Prove same-token revert, conflict refusal, value ABA limitation and app reconciliation overwrites. Measure peak allocation and repeated capture/release; detached surviving views must not grow registry storage across captures. Run supported-runtime tests before publishing a capability matrix; no universal system-app support.

**Gate D — textured inspector separately.** Before claiming the requested 3D composition, obtain actual per-node imagery with documented solo/subtree/layer semantics, geometry and capture timing. Validate overlapping/transparent children, clipping, transformed parents, blur, shadows, video/Metal and missing/protected surfaces. Never hide/unhide application views automatically as an unreviewed texture fallback. Verify renderer picking, artificial depth, source transforms and independent LCD alignment. Geometry tests and one screenshot cannot satisfy this gate.

### Go/no-go summary

Proceed to headless harness and owned-fixture experiments with the weak registry as the first candidate. Do not enable production edits yet. Blocking unknowns are stable target anchor/weak semantics in the actual LLDB context, safe main-thread injection entry, failure-time target state and cleanup, actual UIView replacement rejection, and supported runtime/signing conditions. Texture feasibility is a separate blocker for a complete textured inspector. If weak registry gates fail, evaluate the nonce alternative against the same gates plus per-view side effects/orphan budget; do not silently fall back to raw pointers or an indefinitely paused app.
