# Simulator accessibility research

Research date: 2026-11-09. Stage: research only; no runtime capability was enabled.

## Decision inputs

Extend the existing LCD semantic inspector rather than replace it with a label list or touch simulator. Its private CoreSimulator translation route is a plausible backend for hierarchy, detailed attributes, hit testing and typed accessibility actions. Each additional capability still needs a bounded runtime probe. Keep audits behind a separate backend: XCTest offers a documented testing route, while Accessibility Inspector uses additional private audit/device infrastructure. Neither a selector nor a private entitlement found in an Apple binary establishes a usable third-party API.

This report distinguishes **documented platform contracts**, **current source observations**, **installed binary metadata**, **public reverse engineering**, and **proposed contracts**. No app, Simulator, debugger, IPC connection, input, installation or restart was started for this research. Existing dirty/untracked work is outside this document's ownership.

## What “accessibility instruments” can mean

| Tool or API | Actual scope | LCD implication |
| --- | --- | --- |
| Accessibility Inspector | Standalone Xcode tool: target device/process, point selection, Basic/Actions/Element/Hierarchy sections, accessibility navigation, speech and audits. Actions include activation, scrolling and custom actions. [Apple workflow](https://developer.apple.com/documentation/accessibility/inspecting-the-accessibility-of-screens), [WWDC19](https://developer.apple.com/videos/play/wwdc2019/257/) | Model reading, selection, capabilities and explicit execution separately. AX navigation order is not necessarily view-tree traversal order. Do not claim VoiceOver equivalence from a DFS list. |
| Instruments UI Automation | Historical JavaScript automation instrument using accessible UI information. Apple deprecated UIAutomation in Instruments in Xcode 7 and directed developers to UI testing. [Xcode 7 release notes](https://developer.apple.com/library/archive/documentation/Xcode/Conceptual/RN-Xcode-Archive/Chapters/xc7_release_notes.html), [original Automation workflow](https://developer.apple.com/library/archive/documentation/AnalysisTools/Conceptual/WhatsNewInstruments/NewFeatures42/NewFeatures42.html) | This is not a current general-purpose audit integration contract. Instruments transport names in Apple binaries do not resurrect the old API. |
| XCTest / XCUIAutomation | UI test query/action framework and automated accessibility audits. Current Xcode recording/replay is UI testing. [XCUIAutomation](https://developer.apple.com/documentation/xcuiautomation), [WWDC25 recording](https://developer.apple.com/videos/play/wwdc2025/344/) | A separate managed UI-test session can produce audit results; linking the framework into mac-cu alone does not establish a working runner/session. |
| macOS AX client API | Documented cross-process host accessibility objects, attributes, actions, hit testing and observers. [AXUIElement API](https://developer.apple.com/documentation/applicationservices/axuielement_h) | Suitable for host apps with appropriate accessibility permission. It does not document transport into a guest Simulator app. |
| Simulator guest AX bridge | AXPTranslator plus SimDevice request transport, both private. Guest accessibility is translated to Mac-style objects. | Existing backend; keep its support/version/failure status visible. Translated NSObjects are not automatically AXUIElementRef objects. |
| UIKit view capture / 3D | Separate debugger-based observation of backing views and geometry. | AX nodes are semantic objects, not all UIViews, SwiftUI declarations or physical layers. Hierarchy-depth exploded Z is a visualization; it does not measure physical transform Z. |

Inspector also offers settings experiments; these change device state and require their own restore/ownership contract. They are not read-only inspection. [Apple settings workflow](https://developer.apple.com/documentation/accessibility/testing-system-accessibility-features-in-your-app).

## Current repository behavior

Source paths below are relative to `mac-computer-use/skills/mac-computer-use/scripts/mac-cu-src/`. Source hashes are retained in the raw evidence directory. These are source observations, not live tests.

- `SimulatorAccessibility.swift:12–49`: `SimulatorElement` stores role, label, identifier, stringified value, frame, depth and screen size; optional enabled and action names are exposed. Missing value, unsupported value and empty string are collapsed. Native value types, traits, help, parent IDs and child IDs are absent from inspection data.
- `:55–144`: token-bound `SimulatorAccessibilityBridge` registers SimDevice; `AXPTranslator.sharedInstance` receives `bridgeTokenDelegate`. Its callback invokes `sendAccessibilityRequestAsync:completionQueue:completionHandler:` and synchronously waits up to five seconds. Frame conversion returns its input; root-parent delegate returns nil. Front app lookup calls `frontmostApplicationWithDisplayId:bridgeDelegateToken:` with **display ID 0**.
- `:150–203`: translated root comes from `macPlatformElementFromTranslation:`; per-node translation receives the device token. Recursive children yield a flattened DFS list capped at 600 elements / depth 40. Truncation is not reported. Role drops the `AX` prefix. Geometry includes SpringBoard and root rotation special cases plus `ActiveScreen` presentation transforms. Action names and `AXEnabled` are read, but capability availability is not represented separately from an empty list.
- `Simulator.swift:793–803,841–860`: inspection scope covers device/screen, presentation and guest rotations and point size. Read checks front PID before/after collection. It reports `selectionMethod = normalized AX frame candidates`; `hitTestSelectorAvailable` only tests selector presence. There is no actual backend hit test in that operation.
- `SimulatorToolbox.swift`, `SimulatorElementBrowser.pick(at:)`: point picking filters previously read rectangles and sorts deepest first. It selects the first candidate after the explicit point pick; it sends no guest action. This can disagree with occlusion, nonrectangular hit areas and AX's own hit-test policy. The list retains alternate candidates.
- LCD selected AXPress (`pressSimulatorInspectionElement`, `:317–333`) checks front PID and a unique exact `inspectionData` match in a fresh collection, requires advertised `AXPress` and enabled != false, then calls BOOL `accessibilityPerformPress`. It does not verify resulting guest state. Legacy name-based `pressSimulatorElement` selects first matching name and calls press without the same advertised-action/uniqueness checks. Preserve and explicitly reconcile these two policies during design.
- `Simulator.swift:985–1000`: selected touch tap checks PID, unique fresh row, wholly onscreen positive frame and enabled state, then sends HID at its center. Touch is a distinct operation; AXPress can legitimately apply without a touchable center.
- `SimulatorToolbox.swift` and `SimulatorWindow.swift`: local pick mode suppresses LCD mouse/key forwarding, Escape exits, stale/failed reads clear selection, and geometry/input/action/close paths invalidate inspection. After action, UI requests a new read; it does not automatically publish a post-action snapshot. Autonomous guest changes can still leave displayed data stale.
- `SimulatorViews.swift:127–173`: general capture remains unavailable; fixture `validationOnly` and LCD overlay restrictions remain. `SimulatorViewHierarchy.swift` uses capture-scoped identity. Existing fixture 14-node join / seven zero-error corner comparisons are historical narrow evidence, not reverified here and not general-app, LCD, 3D or mutation evidence. `docs/simulator-inspector.md` and `docs/simulator-view-capture.md` remain authoritative for that boundary.

| Capability | Documented contract | Guest route / remaining evidence |

| AXPress / adjustment | Host advertises action names and `AXUIElementPerformAction`; UIKit `UIAccessibilityAction` provides increment/decrement for adjustable controls. ## Candidate implementation contracts

These are design inputs, not implemented API promises.

1. **Snapshot:** immutable `captureID`, backend/version, read start/end timestamps, device UDID and boot epoch if obtainable, display identity, PID/start seconds+microseconds/resolved executable path/device identity, orientation/presentation/viewport revision. Each node gets a snapshot-local opaque ID, parent ID and ordered children. Keep truncation/cycle/timeout flags and per-field `available / unsupported / failed / redacted` status. Never make blank label/value mean unsupported.
2. **Identity:** translated `objectID` may improve within-session correspondence after validation, but is not a durable identifier. `accessibilityIdentifier` may be absent or duplicated; pointer and PID may be reused. Keep live objects only in a bounded token/target session. Resolve a UI handle server-side against its exact capture; never accept object addresses or user-supplied selectors. Parent traversal can use captured edges without new IPC; refreshing a parent is a new observation.
3. **Pick/read:** preserve rectangle-candidate mode and name it honestly. A verified backend hit test returns its provenance, display, point space and target identity; do not silently substitute the deepest rectangle on failure. Show role/label/value, traits with raw bitset plus validated decoded names, help, identifier, frame/activation point if present, enabled/focused state, supported actions and attribute types/settable state. Role mapping does not reconstruct UIKit traits.
4. **Mutation:** typed enum operations `press`, `increment`, `decrement`, `customAction(handle)`, `setValue(typedValue, expectedOldValue)`. Require explicit UI action, capability advertisement, nonstale capture, target lifetime/display revalidation, unique element resolution and current capability reread. Do not route ambiguous action to touch. Limit setters to proven string/number/bool/range cases with bounds/units/length/secure-field policy; do not guess from stringified values. Keep traits, label, role, frame and arbitrary attributes read-only until separately supported.
5. **Result:** report dispatch accepted/rejected/unknown separately from observed result; include before/after capture IDs, value changes and target identity. Reread even on BOOL success. If press navigates away, report changed target rather than a stale row. A timed-out write has uncertain delivery: **no automatic retry**. Reconcile by read. Restore is another explicit capability-checked mutation, not rollback of application side effects.
6. **Lifetime/races:** validate PID/start/path/device before read and immediately before action. Reject unknown identity rather than weaken matching. Front PID alone permits reuse and same-process screen replacement. Capture matching is not atomic with dispatch; expose this remaining race and keep the window small. Expire action handles on refresh, guest change, foreground change, display/fold/orientation change, pending action, close, transport error and timeout. Notifications can accelerate invalidation but cannot prove freshness.
7. **Coordinates:** retain source frame and coordinate-space provenance separately from LCD presentation frame. Resolve actual translation display IDs instead of hard-coded 0 before claiming multi-display support. Validate app versus SpringBoard, every orientation, outer/inner foldable display, host-only rotation, LCD fitting/letterboxing and backing scale. Accessibility host top-left points, guest shown points, fixed UIKit coordinates and host AppKit points are distinct spaces. **Never feed fixed-coordinate UIKit polygons into guest AX rectangle rotation.** Fail closed when the display mapping is unknown.
8. **Input/UI:** keep host inspector selection/focus distinct from guest AX focus, guest text focus and VoiceOver focus. Picking and host editing must consume mouse/keyboard locally; Escape cancels, held HID releases on focus transfer/close, and focus returns to the invoking host control. Guest focus-changing actions require explicit commands. Show reading/stale/unavailable/unsupported/permission/target-changed/truncated states and action-specific outcomes. Preserve values entered in the host editor when a stale write is rejected, but require a new target selection before resubmission.
9. **Audit record:** backend, runID, target lifetime/display, current-screen timestamp, requested/supported categories, settings/configuration, execution status, findings with descriptions/evidence references and optional element handle; original and ignored findings remain distinguishable. Do not join audit elements to current AX/UIView nodes solely by label/frame. Dynamic-type audits may disturb layout/settings; isolate and restore only state owned by the session.

An AX value change alters application runtime state and can trigger app persistence/network effects. It is not an edit to Swift/SwiftUI source. Inspector property overrides and debugger edits are also runtime experiments, not source persistence. Debugger expression evaluation can execute target code; LLVM timeout/unwind options do not undo effects. [LLVM SBExpressionOptions](https://lldb.llvm.org/python_api/lldb.SBExpressionOptions.html). Keep the existing no-arbitrary-expression contract.

## Failures, validation and next experiments

**Source-level objections to address:** five-second callback wait has no explicit timeout status, request cancellation or whole-tree deadline. Many lazy attribute fetches can exceed a useful UI budget. Semaphore completion after timeout needs a safely synchronized result lifetime. Running synchronous translation on its callback completion queue could deadlock. KVC and `class_getMethodImplementation` are not a complete unsupported-selector/ABI guard; unknown keys can raise ObjC exceptions and an IMP lookup alone does not prove a usable implementation. The process-global translator/delegate needs serialized initialization, token ownership and defined behavior across windows. Tree cycles/truncation, target changes mid-read and backend exceptions need typed failures. These are review inputs; this task did not modify them.

| Follow-up probe | Narrow pass condition / resulting decision |
| --- | --- |
| GUI-free metadata probe in an isolated helper | Load only required frameworks; enumerate classes, selectors and exact method encodings without bridge requests. Confirm installed AXP signatures, increment/custom-action/setter APIs. Deadline and exact helper instance budget; no target service calls. Missing ABI disables that capability. |
| Read-only fixture AX probe | On one already claimed device, record target lifetime and display; compare parent/children, help/traits/value types and action enumeration with fixture expectations. Include duplicate identifiers, ignored/grouped elements, virtualized list, empty/secure values, cycles/truncation mocks. Verify whole-request timeout/cancel and no HID. |
| Point/geometry probe | Independent fixture landmarks and overlapping/nonrectangular elements compare backend hit test versus rectangle candidates. Check foreground app and SpringBoard in four orientations; separately claim each foldable/multiscreen case. Capture coordinates alone do not pass LCD alignment: observe rendered LCD highlight and point mapping at multiple host scales/rotations. |
| Typed action/edit probe | Fixture counters/state verify exactly one press, increment/decrement, distinct duplicate-name custom actions and supported text/numeric setter. Unsupported/nonsettable/disabled/ambiguous/stale PID/start/path/capture/display cases send zero writes. Reread verifies result; simulated lost reply produces uncertain state and no retry. Prove text edits preserve intended value semantics; do not use personal apps/data. |
| Dynamic-change/input probe | Replace node with identical properties; switch app, restart/reuse PID, change screen/fold/orientation, move element autonomously, close during request and cancel. Verify handle invalidation, safe focus restoration, local typing/picking without guest input and release of held keys/pointers. Unsupported change subscription leaves manual refresh clearly visible. |
| Official audit backend spike | A minimal managed UI test calls documented audit API on a fixture with known findings. Capture successful zero findings, findings, filtered findings, unavailable destination and execution failure distinctly. Verify requested categories against destination. Do not enable private audit transport based on service strings. |

No live probes above were executed. Before any native launch, follow `docs/native-check-safety.md`: prove helper/unknown/inherited-entry dispatch without GUI; run its safety regression; use a parent watchdog with deadline, exact executable budget and owned cleanup; one foreground owner and existing input guards. No broad process-name cleanup or target signals. A future test must own/restore its device state and must not reboot, install into, or commandeer unrelated sessions. Keep capture, rendered LCD, live action, physical-device and installation evidence separate.

**Blocking unknowns for design:** installed AXP ABI and custom action invocation; true display-ID mapping; guest notification availability; setter fidelity and secure value policy; snapshot-lifetime element IDs; audit runner/session ownership and result import. Apple's private audit transport handshake/authorization is unproven. None blocks designing the typed boundary or retaining existing reading/picking/press behavior; each blocks claiming its corresponding new capability works.
