# Simulator AX Objective-C boundary

`SimulatorAXAdapter.h/.m` is a synchronous, closed-operation boundary for the installed arm64 ABI recorded in `simulator-ax-abi-probe.md`. It does not load AXP, construct its singleton, send bridge requests, own a Simulator, or establish guest semantic support. Nothing currently links this adapter into Swift. Existing Swift/KVC paths remain unchanged pending the foreground owner's fixture release and lead integration.

## Integration

Compile `SimulatorAXAdapter.m` once with the same SDK, architecture and deployment target as the canonical Swift executable, using `clang -fobjc-arc -fobjc-exceptions -fobjc-arc-exceptions -fblocks -Wall -Wextra -Werror -c`. Link its object into the Swift build with Foundation, AppKit and CoreGraphics available. Add `SimulatorAXAdapter.h` to a bridging header and pass that header to `swiftc -import-objc-header`. Do not compile with `SAX_ADAPTER_TESTING` in a production build. The macro changes only compiled class-name constants and exposes a signature-comparison test function; there is no environment, argument or request switch that enables it. The fake classes are separate test sources.

Preserve all production helper argument dispatch and native input guards when wiring the build. This task deliberately does not change `setup.py`, Swift, manifests, existing tests, fixture resources, CHANGELOG, installed app or distribution version.

## API and results

All operations are named methods or closed `SAXField`/`SAXAction` enums. No caller can provide an arbitrary selector, attribute, KVC key, expression or address. `frontApplication`, `platformElement`, `elementAtPoint`, bridge delegate/token installation, token, PID and objectID cover translator and translation plumbing. The point API is translator `objectAtPoint:displayId:bridgeDelegateToken:` and returns a translation object; convert it explicitly. No element context hit-test fallback exists. Display mapping is supplied by the caller; zero is not inferred. PID is signed Int32 and objectID is UInt64. Element PID, traits and display identity are not invented.

`read` separates semantic fields, children/parent, actions, custom actions, protection and geometry. CGRect/CGPoint have explicit struct call signatures. Typed value results are strings or finite numbers (including boolean NSNumber); unsupported structured values are rejected. Strings are capped at 65536 UTF-16 units and arrays at 1024 members. Nil, empty, missing selector, incompatible ABI, unsupported capability, invalid result, exception, redaction and bound failure have distinct status codes. Zero scalars are valid values. Finite geometry is required.

`SAXResult.objectValue` is a strong ARC reference. Strings and numbers are copied; arrays are shallow immutable copies after member validation. Opaque elements, translations and system custom actions remain live objects and are not snapshots. The caller must not serialize or expose them as generic property access. Retaining a result across an autorelease pool is supported. Retaining a result does not retain a bridge delegate through AXP's weak reference or freeze guest state.

Every call validates receiver lineage, the first concrete defining method's owner, argument count, parsed return/argument encodings and size/alignment before obtaining and using that method's IMP. Raw installed encodings are retained in ABI error diagnostics. Numeric frame offsets are not used as a compatibility criterion. Overrides and forwarding-only implementations are rejected. The profile is arm64 only; other architectures return unsupported ABI. The caller must prevent concurrent runtime method replacement. This boundary does not defend against malicious in-process swizzling or forged runtime classes.

## Protection and capabilities

`SAXProtectionUnknown` is explicit. AXValue reading and writing require caller-established current guest clear status, inherited `isAccessibilityProtectedContent == NO`, and no secure subrole. The inherited getter alone cannot establish clear guest status. Unknown or protected status prevents the value getter and setter from being invoked. A protection getter/subrole error propagates without exposing a value. No protected-content setter is exposed. `valueSettable` only reports observations and never grants fixture/runtime qualification.

Mutations require a separate `qualified:YES` supplied by the caller after guest/runtime qualification, plus current enabled state and advertisement. This boolean is an internal integration precondition, not a user-controlled transport option or an authorization token. Press requires AXPress and returns BOOL dispatch feedback. Increment/decrement require their current AX action names and call the installed void methods. Escape requires AXCancel and also returns void. No generic action dispatch is exposed.

Value writes require advertised AXValue, current successful `accessibilityIsAttributeSettable:`, explicit clear protection and guest qualification. The setter is only `accessibilitySetValue:forAttribute:` with value first and constant AXValue second. Inherited `setAccessibilityValue:` is never used. Caller qualification must restrict the supported guest value type and domain bounds; finite scalar validation here is insufficient to establish a valid guest edit. No coercion from strings to numbers occurs.

Custom invocation retains the exact current-session action supplied by the caller and confirms identity in the current advertised collection. Duplicate names remain distinct objects. The action's name/handler/target/selector accessors must have system-defined lineage and exact ABI. System AppKit handlers use the declared `BOOL (^)(void)` contract. A copied handler or strong local target remains alive during invocation. Target methods must be concrete BOOL no-argument or BOOL one-object methods; the latter receives the retained action. Only the selector read from the system action is used. No first-by-name resolution or caller-supplied selector is accepted. Arbitrary blocks or fabricated actions must never enter this API through transport.

## Dispatch, exceptions and ownership

Observation and operation dispatch are separate methods. `mutationOutcome` starts at not-entered, becomes dispatched for a returned void or true BOOL, and becomes rejected for false BOOL. Dispatched does not mean observed guest success. `setterEntered` becomes true immediately before the setter IMP call. An exception after invocation entry yields uncertain outcome; an exception during preflight yields not-entered. The boundary cannot determine whether the guest received a request before a private method threw. Neither outcome is a license for automatic retry. Bridge/token setters also report invocation uncertainty.

`@try/@catch` converts Objective-C NSException only. It cannot contain memory faults, aborts, blocking calls or hangs. Exception reason/userInfo are omitted because they can contain protected values. Treat an exception as a session invalidation signal. ARC exception cleanup is required for retained local action/target/block references. Calls are synchronous and execute once; no delayed blocks, timers or retry paths are created.

The caller owns executor serialization, global translator/delegate/token lifetime, current session/action binding, target/PID lifetime, display mapping, whole-read monotonic deadline, node/depth/cycle bounds, cancellation, operation deduplication and postcondition reread. It must discard stale observations and reconcile uncertain mutations. A deadline cannot interrupt a blocking in-process private call; hard containment requires a separate supervised transport design. This adapter alone does not establish safe editing.

## Headless verification

Run `python3 mac-computer-use/tests/simulator-ax-adapter/run.py`. It builds production and compile-time fake variants into a unique `/tmp/mac-pilot-ax-adapter.*` directory. It never loads AXP or constructs NSApplication. Existing `native_check_support.py` checks helper/unknown/inherited entry (exit 64), then supervises the explicit CLI root with a 20-second deadline and exact executable instance budget one. All output and source hashes stay outside Git. The harness checks fake lineage/ABI rejection, missing methods, typed returns, collection members, protection, advertised capability, BOOL/void dispatch, setter ordering, uncertainty, custom handlers and target signatures, duplicate names and autorelease-pool ownership. This establishes boundary behavior only; it is not guest fidelity, point mapping, bridge liveness, or safe-editing evidence.
